# CryptoPay — безопасность

Документ описывает модель угроз внутреннего криптопроцессинга, архитектурные решения по безопасности,
результаты аудита и обязательный чеклист перед запуском.

## 1. Контекст и модель угроз

Сервис **внутренний**: им пользуются только собственные проекты владельца. Наружу (для конечных
плательщиков) открыты только страница оплаты `/pay/:id` и `GET /api/public/invoices/:id`.
Публичной регистрации мерчантов нет, KYC нет, кастодиальных функций нет.

| Актор | Доступ | Чем рискуем |
|-------|--------|-------------|
| Конечный плательщик | `/pay/:id`, `/api/public/*` | перебор id счетов, DoS, XSS на странице оплаты, open redirect |
| Собственный проект (merchant) | `/api/v1/*` по `cp_live_` ключу | утечка ключа = создание счетов и чтение данных этого мерчанта; SSRF через `webhook_url` |
| Сотрудник (admin) | админка, Sanctum | компрометация аккаунта = управление сетями/контрактами/мерчантами, симуляция платежей |
| Watcher | `/api/internal/*` по `INTERNAL_API_TOKEN` | подделка «транзакции» = фиктивное зачисление |
| Внешние RPC / TronGrid | данные о блоках | ложные/отсутствующие события, reorg |
| Инфраструктура | docker, env, логи | утечка секретов, доступ к БД/Redis |

**Самые опасные исходы** (в порядке приоритета):
1. Зачисление без реального перевода в сети (подделка internal-запроса, включённая симуляция в проде).
2. Двойное зачисление или зачисление не тому мерчанту/счёту.
3. Принятие транзакции, которую потом откатил reorg, или транзакции с `status = failed`.
4. Компрометация админа или API-ключа мерчанта.
5. SSRF из вебхуков во внутреннюю сеть compose.
6. Утечка секретов (API-ключи, webhook secret, internal token, APP_KEY) через логи и ответы.

## 2. Архитектурные решения

- **Некастодиальная схема на xpub.** Сервис хранит только расширенные публичные ключи и выводит из них адреса
  депозитов. Приватных ключей и мнемоника в системе нет, вывод средств не реализован по дизайну.
  Утечка xpub = потеря приватности (можно вычислить все адреса), но не средств.
  xpub задаётся в админке (страница Wallet, `wallets.xpub`) и перекрывает env `EVM_XPUB`/`TRON_XPUB`. Поскольку xpub —
  всё-таки приватность всех депозитов сразу, он: не входит в `$fillable`/`toArray()` модели, наружу отдаётся только
  маской (10 + `…` + 6) и никогда полностью — даже админу сразу после сохранения; в `audit_logs` пишется тоже маска;
  не логируется ни в Laravel (сообщение исключения Guzzle с телом запроса намеренно не логируется), ни в watcher
  (redaction по шаблону + сообщения ошибок деривации не содержат ключ). Запись/удаление — только роль `admin`,
  чтение (маска) — `admin` и `viewer`.
- **Сеть без кошелька не принимает деньги.** Если для сети нет ни `wallets.xpub`, ни env-ключа watcher'а
  (`/health` → `derivation.evm|tron`), она исключается из `options` публичного счёта и из `GET /api/v1/networks`,
  создание счёта на ней → `422`, аллокация → `503 wallet_not_configured`. Это закрывает сценарий «счёт выставлен,
  плательщик перевёл, а адрес принадлежит несуществующему кошельку».
- **Один адрес на счёт**, адреса не переиспользуются: платёж однозначно привязывается к счёту и мерчанту.
- **Зачисление только по `confirmed`**, ровно один раз (`credited_at`, блокировка строки, транзакция БД).
  `confirmed → detected` игнорируется, `orphaned` (reorg) делает обратную запись в ledger.
- **Подтверждения**: Ethereum 12, BSC 15, Tron 19 блоков (настраивается). Для EVM перед `confirmed`
  проверяется receipt (`status = 1`, совпадение hash блока), для Tron — solidity-высота и `receipt.result = SUCCESS`.
- **Строгая фильтрация событий**: только `Transfer` настроенных контрактов USDT/USDC, только на наши адреса,
  сумма декодируется в BigInt с decimals из настроек, а не из данных сети.
- **Разделение секретов**: `X-Internal-Token` для watcher ↔ backend, `cp_live_` ключи (хранится sha256),
  Sanctum-токены для админов, webhook secret на мерчанта (HMAC-SHA256 с timestamp).
- **Сетевая изоляция**: наружу опубликован только порт nginx; postgres, redis, php-fpm и watcher доступны
  только внутри сети compose; `/api/internal/*` дополнительно закрыт на уровне nginx для внешних адресов.
- **Деньги — только decimal(36,18) и bcmath / BigInt**, float не используется.

## 3. Сравнение с критериями референса (paymento.io, обзор шлюзов)

| Критерий из обзора | У кого «хромает» по обзору | CryptoPay |
|--------------------|----------------------------|-----------|
| Настоящая некастодиальность (средства сразу у мерчанта) | NOWPayments (псевдокастодиальный промежуточный кошелёк), Coinbase Commerce, BitPay, CoinGate (кастодиальные) | адреса из xpub владельца, промежуточных кошельков нет |
| Скрытые комиссии за форвардинг/вывод | NOWPayments, BitPay, CoinGate | внутренних комиссий нет вообще, плательщик платит только сетевую |
| USDT TRC‑20 и мультичейн | Coinbase Commerce (слабая поддержка TRC‑20), BTCPay (в основном BTC) | USDT/USDC в ERC‑20, BEP‑20, TRC‑20 |
| KYC / обязательный email плательщика | Coinbase Commerce, BitPay, MoonPay | email необязателен, KYC нет |
| Непрозрачная модель хранения | Cryptomus | вся логика в открытом коде, документирована в SPEC.md |
| Зависимость от платформы / блокировка аккаунта | все кастодиальные | нет внешней стороны, которая может «заморозить» средства |
| Нужен собственный сервер и техподдержка | BTCPay Server | то же ограничение: сервис self‑hosted, ответственность за инфраструктуру на владельце |

Обзор не затрагивает технические аспекты (подтверждения, reorg, подписи вебхуков, защиту API) — они
покрыты разделами 4–5 ниже.

## 4. Результаты аудита

Аудит проведён по трём слоям с исправлением всех находок уровня low и выше. Детальные отчёты с номерами строк
и тестами — в истории коммита; ниже сводка.

### 4.1 Backend (Laravel) — 2 critical, 6 high, 11 medium, 5 low, всё исправлено

| Уровень | Находка | Исправление |
|---------|---------|-------------|
| critical | Повторная отправка транзакции с большей суммой перезаписывала уже зачисленную сумму | после `credited_at` поля суммы/валюты заморожены |
| critical | Откат (reorg) списывал текущее значение `amount`, а не то, что реально зачислено | сумма отката = нетто ledger по транзакции, клемп в ноль + critical-лог |
| high | Перевод в другой валюте (USDC на USDT-счёт) закрывал счёт как оплаченный | учитываются только транзакции в валюте счёта; чужая валюта зачисляется на баланс своей валюты |
| high | Симуляция платежа включалась одним флагом конфига | нужно `SIMULATION_ENABLED=true` **и** `APP_ENV` local/testing; каждая симуляция в audit log |
| high | Нет защиты от SSRF в `webhook_url` | запрет приватных/loopback/link-local/metadata адресов и имён compose, редиректы не следуются, таймаут 10с; `WEBHOOK_ALLOW_PRIVATE=true` только для локального демо |
| high | Sanctum-токены админов не истекали | срок 12 ч (`SANCTUM_EXPIRATION`), отзыв при logout |
| high | Таблица `audit_logs` не заполнялась | `AuditLogger` на все чувствительные действия (мерчанты, ключи, секреты, сети, контракты, пользователи, отмены, симуляции) |
| high | Internal API принимал placeholder-токен из репозитория | 503 пока `INTERNAL_API_TOKEN` не заменён; сравнение constant-time |
| medium | Деактивированный админ сохранял доступ по старому токену | middleware `EnsureActiveUser` подключён с правильным приоритетом |
| medium | Можно было деактивировать/понизить последнего админа | guard последнего активного админа |
| medium | Слабая валидация internal-payload (`amount_raw` мог быть отрицательным, tx_hash любой) | `amount > 0`, согласованность `amount`/`amount_raw`/decimals, формат tx_hash по сети, лимит batch 200 |
| medium | `success_url`/`cancel_url`/`webhook_url`/`image_url` принимали `javascript:`/`data:` | только абсолютные http(s) |
| medium | `metadata` без ограничений попадало в каждый вебхук | объект ≤ 8 КБ, ≤ 50 ключей, глубина ≤ 5 |
| medium | Суммы вроде `0.000` проходили валидацию | правило `PositiveAmount` с учётом decimals токена |
| medium | Пароль админа от 8 символов | минимум 12 |
| medium | Нет security-заголовков, авторизованные JSON кэшировались | `SecurityHeaders`: nosniff, `Cache-Control: no-store` |
| medium | Тело запроса ограничивалось только php.ini (20 МБ) | 1 МБ на весь API, 413 в стандартном конверте |
| low | APP_KEY и демо-ключ мерчанта печатались в логи контейнера | только в `APP_ENV=local` |
| low | Ошибка watcher раскрывала внутренний адрес | общий текст вне local |
| low | Throttle логина отдавался как 422 | корректный 429 |

Принято без изменений: UUIDv7 у счетов (74 случайных бита + rate limit, перебор нереален), лимит `/api/public` 120/мин
(чекаут поллит каждые 5 с), SSRF-guard не блокирует неразрешимые DNS-имена (доставка всё равно упадёт).

### 4.2 Frontend и SDK — 2 high, 7 medium, 8 low, всё исправлено

| Уровень | Находка | Исправление |
|---------|---------|-------------|

| Уровень | Находка | Исправление |
|---------|---------|-------------|
| critical | `/api/internal/*` был доступен с опубликованного порта; allowlist по приватным IP не помог бы (трафик хоста приходит с адреса docker-моста) | internal API вынесен на отдельный `server` nginx на порту **8081**, который compose не публикует; с `:80` всегда 404. `BACKEND_URL=http://nginx:8081` |

| high | Неавторизованный `/health` отдавал RPC URL с ключами из текстов ошибок | `redact.ts`: URL → `scheme://host/***`, секреты маскируются по значению |

## 5. Чеклист перед запуском

- [ ] `make keys` → мнемоник хранится офлайн; xpub задан для всех рабочих сетей — в админке (Wallet) либо
      через `EVM_XPUB` / `TRON_XPUB` в `.env`. На странице Wallet ни одна сеть не должна быть «Not configured».
- [ ] Первые адреса, выданные после смены xpub, сверены с собственным кошельком (кнопка «Preview addresses»).
- [ ] `APP_ENV=production`, `APP_DEBUG=false`, `SIMULATION_ENABLED=false`.
- [ ] Свои значения `APP_KEY`, `INTERNAL_API_TOKEN` (≥ 32 случайных байт), `DB_PASSWORD`, `REDIS_PASSWORD`, `ADMIN_PASSWORD`.
- [ ] `WEBHOOK_ALLOW_PRIVATE=false` (вебхуки только на публичные https-адреса ваших проектов).
- [ ] HTTPS перед nginx (reverse proxy/ingress с TLS), `APP_URL` = внешний https-адрес.
- [ ] Собственные или платные RPC-ноды (`ETH_RPC_URL`, `BSC_RPC_URL`), `TRON_API_KEY`.
- [ ] Бэкапы PostgreSQL; том `watcher-data` сохраняется между деплоями.
- [ ] Мониторинг: `watcher_healthy` по сетям в дашборде, алерт при лаге > 50 блоков.
- [ ] Ротация API-ключей мерчантов и webhook secret при смене персонала.
- [ ] Доступ к админке ограничить VPN/IP-allowlist на уровне reverse proxy.
